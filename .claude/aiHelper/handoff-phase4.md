## Key design decisions (for future reference)

| Decision | Value |
|----------|-------|
| **device_uuid = deviceId** | One UUID for both leaderboard and sync. On restore, device B replaces its `deviceId`. Old anonymous leaderboard entries orphaned — acceptable. |
| **Profile UI location** | Inside LeaderboardModal (not a separate modal) |
| **Sync trigger** | Valid `submitWord` only, daily puzzles only |
| **Collision** | 2+ name+PIN matches → picker UI |
| **Disconnect** | Generates new `crypto.randomUUID()` as `deviceId`, clears `profileLinked` |
| **Puzzle IDs** | `${date}-wordle-${length}` format kept permanently — changing it breaks localStorage |

## Architecture constraints (never violate)

- No inline styles — Tailwind utility classes only
- No new npm dependencies without explicit approval
- Game logic in `src/games/*/lib/` must stay pure functions — zero React imports
- Each game reads/writes only its own store slice
- After every change: `npm run test -- --run`, `npx eslint .`, `npm run build` — all must pass
- PowerShell only on Windows — `Select-Object -Last N`, never `tail`
- **Cross-device persistence is Leksokipos-only** — do not add `useGameStateSync` to other games without explicit instruction
- **`(name, pin)` is not a unique key** — never add a UNIQUE constraint on that pair
- **`device_uuid` is a profile identifier** — never update it after the profile row is created
- **FlowerGrid arc radius must equal `CENTER_R`** — changing one without the other breaks the seamless base join
- **Puzzle ID strings are permanent** — `${date}-wordle-${length}` must never be renamed; they are localStorage keys
- **Internal identifiers are stable** — `leksokipos`, `leksiarxeio`, `leksindeseis` in code. UI strings (titles, labels) may change freely without touching routes, types, or directories
