## Remaining work — Cross-device persistence (Leksokipos only)

> **Prerequisite:** human runs the SQL below in Supabase dashboard before the agent starts.

### All decisions locked

| Decision | Value |
|----------|-------|
| **Scope** | Leksokipos only |
| **Identity** | `device_uuid` = the existing `deviceId` from `getOrCreateDeviceId()` — client-supplied, NOT server-generated |
| **Envelope flag** | `profileLinked: boolean` added to `wordgames:state` envelope — true once profile is created or restored |
| **PIN generation** | Auto-generated by server (4 digits). Never user-chosen |
| **Name uniqueness** | Not enforced. Two players named "Νίκος" is fine |
| **Collision handling** | `(name, pin)` is NOT unique — multiple rows can exist. On restore, show picker |
| **Collision picker score** | Score from most-recently-saved `game_state` row (any date); "–" if no state exists |
| **What is synced** | Full game state blob (found words, score, current input) |
| **Sync trigger** | On valid `submitWord` only. Daily puzzles only — custom puzzles never sync |
| **Retention** | 7 days max, matching existing rolling-window policy |
| **Restore hot-swap** | Write fetched state to store slice directly — no page reload |
| **Disconnect** | Generate new `crypto.randomUUID()` as `deviceId`, clear `profileLinked`. Old anonymous leaderboard entries on this device are silently orphaned — acceptable |

### Why device_uuid = deviceId

The `game_scores` leaderboard table already identifies players by `device_id`. If sync used a different UUID, restoring a profile on device B would produce two leaderboard rows for the same player (one per device's `deviceId`). Using one UUID for everything avoids this. On restore, device B replaces its `deviceId` in localStorage with the profile's `device_uuid` — the leaderboard "you" highlight then works correctly on both devices.

### API routes

| Route | Purpose |
|-------|---------|
| `POST /api/profile` | `{display_name, device_uuid}` → server generates PIN, inserts row, returns `{pin}` only |
| `GET /api/profile?name=&pin=` | Returns array of matching profiles (0, 1, or many) with `device_uuid` + `created_at` + `last_active` |
| `POST /api/game-state` | Upsert state blob: `{device_uuid, game_id, puzzle_date, state}` |
| `GET /api/game-state?device_uuid=&game_id=&puzzle_date=` | Fetch state blob for restore |

### User flows

**Create profile (first device):**
1. Player opens the leaderboard modal, sees the profile section (between name editor and day strip)
2. Types display name (blank → "Ανώνυμος"), taps "Δημιουργία"
3. `POST /api/profile` with `{display_name, device_uuid: deviceId}` → returns `{pin}`
4. Modal shows PIN reveal view: **"Ο κωδικός σου είναι: 4829 — σημείωσέ τον!"** + "OK" button
5. After OK: `profileLinked = true` in envelope. Profile section now shows name + "Αποσύνδεση"
6. Existing name-editor section is hidden while `profileLinked` is true
7. `useGameStateSync` begins syncing from this point

**Restore on second device:**
1. Player opens leaderboard modal, sees profile section (no profile active yet on this device)
2. Enters name + PIN, taps "Επαναφορά"
3. `GET /api/profile?name=&pin=` → 0 matches → show error; 1 match → proceed; 2+ → show picker
4. Picker shows each match: created date · last played · score (from most-recent game_state)
5. On selection: replace `deviceId` in envelope with chosen `device_uuid`, set `profileLinked = true`
6. Fetch today's game state via `GET /api/game-state` → hot-swap into store slice
7. Modal closes, game reflects restored state

**Disconnect:**
1. Player taps "Αποσύνδεση" in the profile section
2. Generate `crypto.randomUUID()` → write as new `deviceId`
3. Clear `profileLinked`
4. Profile section returns to "create / restore" view

## Architecture constraints (never violate)

- No inline styles — Tailwind utility classes only
- No new npm dependencies without explicit approval
- Game logic in `src/games/*/lib/` must stay pure functions — zero React imports
- Each game reads/writes only its own store slice
- After every change: `npm run test -- --run`, `npx eslint .`, `npm run build` — all must pass
- PowerShell only on Windows — `Select-Object -Last N`, never `tail`
- **Cross-device persistence is Leksokipos-only** — do not add `useGameStateSync` to other games without explicit instruction
- **`(name, pin)` is not a unique key** — never add a UNIQUE constraint on that pair
- **`device_uuid` is a profile identifier, not a device identifier** — never update it after the profile row is created
- **FlowerGrid arc radius must equal `CENTER_R`** — changing one without the other breaks the seamless base join
