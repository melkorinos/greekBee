The file has 4 separate queue useState hooks, a cascading if/else if in fetchCommunityPuzzles, another one in handleCommunityReviewed, and a 4-deep nested ternary in JSX. The last else branch of the JSX ternary silently owns stavrolekso — any 5th game would inherit that slot incorrectly. The proposal is structurally sound: all four queues are isomorphic (fetch by game slug → store array → filter on review). The only nuance is the card registry must be a render-function map, not a component map, because each card has a different puzzle-data type — a small detail the proposal doesn't spell out.
