Problem

The registry's interface carries only presentation, so every operational fact about a Game is re-typed in a list the compiler never checks against it.

Solution

Widen the registry row to declare slice, leaderboard config, accent and submit kind; derive the twenty lists from it, keeping the deliberate exclusions as typed filters rather than retyped unions.

Wins

  • locality: a Game is one row
  • leverage: 20 lists derive
  • compiler replaces the checklist
  • wip flip stops being manual
Evidence this already bites. Session 121 had to add topothesies to Shell.tsx GAME_IDS by hand — the wip flip alone would not have shown it. HomeTrophyButton.tsx:5 lists six games against a nine-id prop. deploymentReadiness.test.ts has no entry for logopaignio or topothesies data files. Shell.test.tsx:153 asserts 6 of 10 drawer hrefs.
Not in scope: SliceId ≠ RegistryGameId is a locked decision — stavrolekso and leksikastirio have no store slice by design. Deriving it means slice: SliceId | null on the row, never collapsing the two unions.

Problem

Three Profile Page components hand-roll fetch, parse, cancel and catch against endpoints sync.ts already wraps — and TrophyCase re-derives the tier-crossing rule locally, so the Profile Page can disagree with the game about which tier a player holds.

Solution

One module owning the player's progress read: it returns a resolved view (earned set, held tiers, selected badge, buckets) with the tier rule applied once by achievements.ts. Components stop knowing URL shapes.

Wins

Timing. TICKET-02 rebuilds this catalog and retires emoji glyphs for drawn marks. Deepening first means the rebuild edits one module instead of three components.

Problem

Solution

One module owning identity-row movement, taking a table accessor rather than reaching for a factory. Two adapters justify the seam: postgres in production, in-memory in tests.

Wins

Half of this is already in your working tree. src/lib/milestoneMerge.ts, games/leksokipos/lib/milestones.ts, api/milestones/ and migration 20260807120000_add_player_milestones.sql are untracked-but-written, collapsing pangram + words into one lane. Deliberately not proposed: a repository per table. table() fails the deletion test in reverse — deleting it would move complexity to call sites, not concentrate it, and it already gives the generated-types guarantee ADR 0017 exists for. The gap is a module above it for the identity aggregate, not a layer below.

A game that wants a different rule says so, rather than owning a copy that quietly drifts.

Problem

Three copies of one concept diverged into three rules, and the divergence is invisible: each has its own green test asserting its own behaviour.

Solution

One pure module over a pool, with the rotation key as a declared parameter rather than a re-implementation.

Wins

  • divergence becomes explicit
  • one date-boundary test set
  • locality: rotation bugs land once
Why only speculative. The other five games resolve their Puzzle through genuinely different paths — community-queue-first for three, deterministic derivation for two — so this unifies three modules, not eight. It earns its keep as a correctness guard for the Slot-Fill family, not as a platform-wide seam. It pairs naturally with candidate 04.

Top recommendation

01 · Deepen the Game registry

It is the cheapest of the five and the only one whose failure mode is already recorded twice in this repo's own history — a finished game filed under «Υπό κατασκευή» for months, and a live game that needed a hand-edit to a second list before the flag flip meant anything. Every other candidate removes duplication that is at least visible; this one removes duplication the compiler cannot see, which is the kind that ships.
