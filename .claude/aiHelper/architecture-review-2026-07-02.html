Pure modules; the interface is the test surface. Maker and route share one set of invariants.

Problem — the four per-game validate() adapters are the only real logic left in the submission routes, yet they live inline in route files: untested, and the Stavrolekso grid/slot invariants (size, slot count, across+down presence) exist only server-side, so the maker learns editability by firing a PATCH and reading the error.

Solution — move each adapter into its game's pure lib module; the route imports it for the lifecycle config, and the Stavrolekso maker imports the same one for pre-flight feedback.

  • 4 adapters become pure, directly testable
  • Locality: invariants live with the game
  • Maker stops guessing across the seam
  • Closes the last lifecycle test gap

2 · One HTTP intake module for the 21 API routes

Strong in-process
src/app/api/**/route.ts — 21 routes; 8 carry a byte-identical parse-or-400 block, 3 more parse with drifting error shapes

Before — every route re-implements intake

After — one deep intake band

HTTP intake module

parse body · uniform error shape · 400/403/500 vocabulary

21 routes keep only domain logic

Problem — "being an API route" has no interface: each file re-owns body parsing, error shape, and status vocabulary, and the shapes have already drifted ({ error: "Invalid JSON" } vs { error: "db_error" } vs the nominations shapes). Deletion test: remove any one block and it must reappear verbatim — a pass-through pattern, not a module.

Solution — a small intake module (parse + respond) that every route calls; the error vocabulary becomes one implementation tested once.

  • Leverage: 1 interface, 11+ call sites
  • Error shape stops drifting
  • Intake tested once, not per route
  • New route = domain logic only
