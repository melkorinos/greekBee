## Session 134 — 2026-08-05: Community Puzzles get a scheduled release; serving stops destroying rows (`/tdd`)

Two defects in `consumeApprovedPuzzle`, both **latent only because all three queues hold zero approved rows** — verified live before touching anything, which is what made the whole change a no-backfill job. (1) The date was ignored: the three loaders each take a `date` but called consume with no filter, so **any** date — including an archive date from the leaderboard day-strip's `?puzzle=` link — served the head of the queue; the date only reached `buildPuzzle` to stamp an id. (2) Consume **DELETEd** on every call and the loaders run on every page load, so a refresh destroyed a puzzle permanently and served the next one — two players on one day could get different puzzles, and a few refreshes drained the queue. **Operator settled the three design questions up front** (auto-assign at approval with an admin override; review UI untouched; no rescheduling), so no grill was needed — worth noting that asking three narrow questions beat running a full design session. Built test-first in four slices: pure `nextFreeScheduledDate(taken, today)` in `puzzleDate.ts` (earliest free date **strictly after today**, gap-filling, order-independent, null-tolerant, UTC-anchored like the rest of that file); consume → non-destructive read keyed on `(status, scheduled_date)`; approve → assigns a date (auto or validated override, **400 before any DB work** on today/past/malformed); the three loaders pass their requested date through. Migration `20260805120000` adds the nullable column to the three consuming tables **plus a partial unique index each** — one puzzle per date, the backstop if two approvals race. **The type system caught the real design question I had glossed:** `.eq("scheduled_date")` failed to compile because `CommunityPuzzleTable` includes **Stavrolekso**, which has no such column (it never consumes) — the fix was a new `ScheduledPuzzleTable = Exclude<…>` + a narrowing guard, so exclusion is structural rather than conventional, and approve branches to a plain undated status flip for it. That was ADR 0017's generated types earning their keep; I initially misread the truncated error as a stale cache and cleared `.next`/`tsbuildinfo` for nothing — **the error text named all four tables, I just didn't read past the `...`**. **Verified against the live DB rather than trusting the mocks** (the s132 lesson): inserted a sentinel scheduled for 2099-01-01 and proved the scheduled date hits, another date misses, the row survives repeat reads, and a second puzzle on the same date is rejected by the index; sentinel deleted, zero remaining. One stale test mock surfaced — `communityPuzzlesReviewRoute.test.ts` stubbed only `update`/`delete`/`eq`, predating approve needing a `select`; the mock was wrong, not the code. Also fixed a self-inflicted fixture error (`toLowerCase()` maps final sigma Σ→ς, so `ΓΑΤΑΣ` never equals `γατασ`). Docs: CONTEXT glossary rewritten (Community Puzzle + Lifecycle now say **serve**, not consume-and-delete; new **Scheduled Date** term), three schema rows corrected, coverageMap rows for all three touched test files. Gates: 189 files / 2328 tests / eslint 0 / build 0 / e2e 7 passed + 2 skipped-by-design. Branch `dev`, commit `d1d888f` — **not pushed**. **Left untouched:** seven modified components + three `archiveNavigation.test.tsx` files already in the tree at session start, deliberately excluded from the commit.


## Session 133 — 2026-08-04: Vres Tin Frasi — the game refused its own solution (`/diagnosing-bugs`)

Operator reported today's puzzle «Η γλώσσα κόκαλα δεν έχει» rejecting the single-letter first word. **Confirmed at the source before theorising:** built a test that assembles the *real* pool exactly as `page.tsx` does, typed the correct answer through the real reducer, and watched it come back «δεν βρέθηκε στη λίστα» — the game would not accept its own answer. Cause: the pool is assembled from fixed-length lists starting at `words-2.json`, so «η» was in no pool at all. Operator's instinct («we have no single-letter list») was exactly right; the only two valid standalone Greek words are **«η»/«ο»** (accent-stripping collapses «ή»/«Η» onto «η»), and the 795k master list has **zero** single-letter entries, so nothing could be derived — it had to be authored. **Measuring scope found a second, larger gap at the other end:** the pool stopped at 8 letters while phrases ran to 15 → **142 of 498 phrases (29%) unsolvable**, the long-word half being the bigger one. Operator chose to keep 8 as a hard ceiling (phrases authored to fit the pool, and no 795k scan on a force-dynamic route) and prune instead. **The decision that matters most:** `words-1.json` lives in `src/data/vrestifrasi/`, NOT beside the other lists — the re-sync adapter regenerates `src/data/leksiarxeio/words-{2,3}.json` from `words-el.json`, so a derived 1-letter file would be **rewritten empty on the next re-sync and silently re-break every article-opening phrase**. Recorded in gameRules + `resyncVrestifrasi.test.ts`; `SHORT_WORD_LENGTHS` deliberately stays `[2,3]`. **The regression test earned its keep immediately** — after the length-based prune it still caught 4 phrases my filter could never have found: a proper noun (Γιάννης, dictionary excludes names), an archaic form (εκράτεις), a genitive (κοράκου, only nominative stocked), and **«Ό,τι» whose comma survives `normalizeLetters` so it can never match any entry**. Also fixed one genuine misspelling (κούκκος→κούκος, correct form already in the pool). A follow-up sweep for those two classes (punctuation, capitalised mid-phrase words) found nothing else — «Θεό»/«Πασχαλιά» are common nouns and present. Corpus 498→**411**. Bounds moved into `VRESTIFRASI` gameRules and the submit modal's player-facing copy now derives from them — it still advertised «3–4 λέξεις, 2–8 γράμματα» while 64 shipped phrases (incl. today's) fell outside that band, so **players could not submit a phrase the daily game itself serves**; widened to 2–9. **Two process notes.** A full-suite run showed 2 Leksodromia failures in a game I never touched; a clean-tree run passed, which looked like my change was implicated — a second run with changes was fully green, so it was a machine-load flake, not a regression. Worth not "fixing" on the first red. Separately, stashing to test that revealed **uncommitted Offline Mode removal work already in the tree** (Shell, ADR 0010, CONTEXT, issue 15 deleted) — left entirely untouched and out of my commit. Also registered `phrases-el.json` in `deploymentReadiness` (statically imported but never listed — a pre-existing gap). Gates: 185 files / 2284 tests / eslint 0 / build 0 (one stale `.next` type artifact needed a clean) / e2e 7 passed + 2 skipped-by-design. Branch `dev`, committed — **not pushed**. **Rotation shifts** (dates map onto array positions) — accepted once, flagged before implementing.
