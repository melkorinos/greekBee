## 🚀 Launch posture (s147–s154)

**Launch = a SOFT launch** — a wider circle, no broadcast, because the site is *already publicly
deployed*, so launch is promotion rather than a change in exposure. That framing is what made the
checklist finite. **`docs/launch-runbook.md` is the whole story** — the committed order of work, the
release-day steps, and what is consciously not being done first. Both launch questions are answered
(sequencing, 2026-08-20: target on or about **27 August 2026**, not hard), so
`.claude/handoffs/launch-readiness.md` is deleted. Read the runbook rather than a second copy here.
Four durable rulings that outlive it:

- **`hidden` is not `wip`** — orthogonal required fields on `GameRegistryRow`, **ADR 0022**. Hidden
  means unlisted, **NOT disabled**: routes stay live by direct URL in every environment. All three
  `wip` Games are hidden. Both flags derive the picker/drawer, probe-tested in
  `registryCoverage.test.tsx`; «Υπό κατασκευή» and the card chip are DELETED, not dormant.
- **`/privacy` is deliberately unadvertised** — one drawer link, no footer, no banner, no consent
  dialog — a posture that holds ONLY while there is no analytics and no ad cookie. **FormSubmit is
  the Platform's one third-party processor**; payload is exactly `message` + `device_id`.
  `privacyPage.test.tsx` **pins the production dependency list**, so an `npm install` fails the
  suite pointing at the page. Any storage/hosting/processor change revisits the page in the SAME
  branch — that includes error monitoring, which is why **ADR 0023** is Vercel-only, no SDK.
- **Runbook order is load-bearing** and `docs/launch-runbook.md` owns it — do not copy the steps
  here. The two constraints behind the order: the reset must FOLLOW the deploy, and the dump must
  be off-machine BEFORE the reset, because it is the only undo on a Free plan with no PITR.
- **A backup never enters a git repo.** This one is PUBLIC and `pg_dump` carries `auth.users`, so
  committing one publishes every signed-in player's email permanently. `db:backup` emits an
  encrypted `.7z` for private Drive. **Stripping `auth` is not the fix** — it restores rows pointing
  at accounts that no longer exist.

OFF by default; `sound-preference` is a standalone `localStorage` key (third carve-out beside `theme-preference`/`leksokipos-variant`, NOT in the envelope). **Deliberately NOT a `GameCapability`** — ADR 0020's criterion is what a Game does to the *shared database*, and a Cue writes nothing. **Licence bar: CC0 or Pixabay Content License, CC-BY REFUSED** (it obliges a permanent credit line — the reason `topothesies/attribution.ts` exists); **Pixabay is NOT CC0** despite universal claims otherwise. **Status: the flag is ON, and exactly ONE Cue is audible — `wordFound`, the blip on an accepted word (operator, 2026-08-25).** A pangram plays that same blip; missing-centre is silent. **Silenced at the selector, NOT deleted:** both other rows stay in `sound.ts`, both MP3s stay in `public/sounds/`, and the hook/preference/toggle are untouched, so restoring either sound is one line in `selectSoundCue` — which is why the test to keep green asserts **no file Cue is reachable at all**, not merely that the rooster is quiet. **The MP3s are post-launch and optional; ADR 0021's "neither ticket ships alone" deploy gate is SPENT — the flag replaced it.** |
