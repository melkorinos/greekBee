| Topic | Decision |

| **Routing** | `/leksokipos`, `/leksiarxeio`, `/leksindeseis`, `/vres-tin-frasi`, `/leksodromia`, `/leksoplegma`, `/stavrolekso` (+ `/[id]`, `/maker`), `/leksikastirio`, `/` picker. Custom: `/leksokipos/[center]/[outer]` |

| **Route envelope** | `src/lib/apiRoute.ts` owns what every `/api` route does before its own logic (ADR 0016). New routes use `parseJson` (never a hand-rolled `req.json()` try/catch) and `requireAdmin` (the `x-admin-secret` header is the **one** admin wire format; a bad secret is **401**, never 403). Error bodies stay `{ error: string }` but the string comes from one of two channels: `jsonError(code, detail?)` for envelope-owned codes — detail is logged, never sent, so **no route returns a raw Postgres message** — or `jsonMessage(text, status?)` for copy the route authors (validation, domain codes like `blocked_word`, and the Greek strings the UI renders verbatim). Deliberate exception: `/api/cleanup-scores` keeps raw messages — cron-only behind `CRON_SECRET`, so they're a diagnostic, not a leak. |
| **Game logic** | Pure functions in `src/games/*/lib/` — zero React imports. |
| **Round spines (two families)** | **ADR 0019.** Two sibling spines, never merged into one generic hook. **Guess family** (leksiarxeio, vrestifrasi) → `useGuessRound`: `status playing/won/lost`, score once on end. **Slot-fill family** (topothesies, posokanei, logopaignio, **leksoplegma** since s129) → `useSlotFillRound` (s128): derived solved/failed(/`gaveUp` where present), decay score posted continuously, session key = puzzle **date**. Each game passes only `{reducer, makeInitialState, toSnapshot, makeRestoreAction, hasProgress}`. The spine owns the **`hasLiveActed`** contract — it issues `RESTORE_STATE` through the RAW dispatch so a restored-untouched round never re-posts via `useLiveScorePost`; a game dispatching its own restore would break it. Snapshot memo keys on projected **values** (not the state object) or every keystroke writes to localStorage — regression-tested. **Leksoplegma's variation** (s129): its reducer's `RESTORE_STATE` **filters restored words against the current puzzle** (stale words dropped — no other member does this); `wrongTrace` is transient/snapshot-excluded; `status` is re-derived, persisted only for the write-guard. Adapter closes over `today` for the id since `makeInitialLeksoplegmaState(puzzleId, puzzle)` takes the id first but the spine passes the puzzle object. A member may lack `gaveUp` but never the live-vs-restore distinction. **`useLeksodromiaRound` is NOT a member** (decay clock + restore must interleave with `reset()`) — do not migrate it. |

| **Leksokipos difficulty** | **s131 rebalance — do not re-litigate the direction.** `softCap` is the ENTIRE source of small-vs-big rank unfairness, not a contributor: without it `frac_of_garden = SCORE_SCALE × top%` for every puzzle identically (`mean × n ≡ total`), spread 0.009. It discounts only the ~75% of puzzles above the knee, so rich gardens were the *fair* ones being made cheap — «make big puzzles harder» is the correct goal, «small puzzles are too hard» is the symptom. The cap STAYS (removing it: words p90 68→214, max 728; trimming to compensate keeps <56% of the corpus) — it deliberately trades fairness for a tedium ceiling. **`SCORE_SCALE` is the only knob that reaches sub-knee puzzles** — tuning knee/k/top% cannot help them, ever. Shipped: `SCORE_SCALE` **0.75**, `SOFT_CAP_K` **400**, knee 400, rank threshold **80% unchanged**. **Never move the top-rank threshold to "fix" difficulty** — `leksokipos-stin-korifi` fires on `rank === TOP_RANK` and achievement ids FREEZE on first deploy; `achievementTuning.theristisFoundRatio: 0.8` is an unrelated 80%, never sync them.
